# Doorbell NVR Card

A custom Home Assistant Lovelace card that provides an NVR-like browsing experience for Reolink doorbell event recordings — MP4 clips, JPG thumbnails, and daily timelapses.

## Features

- **Day view** — browse events for any date with thumbnail cards showing time and preview
- **Week strip** — sliding 7-day navigator with event count badges per day
- **Inline video playback** — click any event or timelapse to play in a modal overlay, no page navigation
- **Daily timelapses** — play compiled timelapse videos when available
- **Media source integration** — uses HA's `media_source/browse_media` WebSocket API, no external server required

## Prerequisites

- Home Assistant with the `media_source` integration enabled (default)
- Reolink doorbell with FTP push enabled, sending recordings to HA's `/media/local/` directory
- File structure: `security/doorbell/YYYY/MM/DD/` containing MP4/JPG files and optional `timelapse.mp4`

## Infrastructure Setup

The card reads files that your Reolink doorbell pushes via FTP. Here's how the pieces fit together:

```
Reolink Doorbell ──FTP push──► Storage Server ──CIFS share──► Home Assistant
   (MP4+JPG)                   (vsftpd+Samba)     mount        (media_source)
```

### FTP Push (doorbell → storage)

Configure your Reolink doorbell to push recordings via FTP to a storage server:

1. Set up an FTP server (e.g. vsftpd) with a dedicated user chrooted to your media directory
2. On the Reolink camera web UI or API, configure FTP push:
   - Server: your storage host, port 21
   - User/password: your FTP credentials
   - Remote directory: the subdirectory under the chroot (e.g. `doorbell`)
   - Mode: AI detection (people, vehicles, visitors, pets)
3. Reolink D340P note: use `GetFtpV20`/`SetFtpV20` API commands, not the older `GetFtp`/`SetFtp`

Files will land at `<chroot>/doorbell/YYYY/MM/DD/` as MP4+JPG pairs.

### CIFS Mount (storage → Home Assistant)

HA must be able to read the FTP upload directory via its `media_source` integration:

1. Share the media directory via Samba/SMB on the storage server
2. In HA: Settings → System → Storage → Add Network Storage → choose "Media"
3. Point the mount at your storage server's SMB share and credentials
4. HA mounts it at `/media/<share_name>/` — this becomes the `media_path` in card config

**Known issue**: HAOS Supervisor may falsely report the CIFS mount as "active" when the kernel mount has timed out. If the card shows empty days or errors, check the mount status from the HA host CLI (`mount | grep cifs`) rather than trusting the Supervisor UI.

### Timelapse Pipeline (optional)

Daily timelapses are not generated by this card. Set up a separate pipeline on your storage server:

1. **Capture**: Run a script on a systemd timer (every minute) that calls the Reolink Snap API and saves JPEGs to `doorbell/YYYY/MM/DD/timelapse/`
2. **Compile**: Run a daily script (e.g. at 01:00) that uses `ffmpeg` to compile the previous day's frames into `doorbell/YYYY/MM/DD/timelapse.mp4`, then deletes the source frame directory

The card detects `timelapse.mp4` at the day level as a playable video. If only a `timelapse/` subdirectory exists (frames not yet compiled), the timelapse button is not shown.

### Mobile Playback Note

Reolink doorbell MP4s may not be faststart-optimized (the moov atom is at the end of the file). On mobile browsers, the entire file must download before playback starts, causing significant delays. To fix, process files server-side after FTP push:

```bash
ffmpeg -i input.mp4 -movflags +faststart -c copy output.mp4
```

## Installation

### HACS (recommended)

Add this repository as a custom HACS repository, then install via HACS.

### Manual

1. Download `doorbell-nvr-card.js` from the [latest release](../../releases) (or build from source)
2. Copy to your HA instance: `/config/www/community/doorbell-nvr-card/doorbell-nvr-card.js`
3. Register in HA: Settings → Dashboards → Resources → Add → URL `/hacsfiles/doorbell-nvr-card/doorbell-nvr-card.js`, type JavaScript module
4. Hard-refresh your browser (Ctrl+Shift+R)

### Build from source

```bash
npm install
npm run build
# Output: dist/doorbell-nvr-card.js
```

## Configuration

Add the card to a dashboard view:

```yaml
type: custom:doorbell-nvr-card
media_path: security/doorbell        # Path under /media/local/
show_timelapse: true                  # Show timelapse button per day
events_per_row: 3                     # Grid columns
```

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `media_path` | string | `security/doorbell` | Media directory path under `/media/local/` |
| `show_timelapse` | boolean | `true` | Show timelapse play button when available |
| `events_per_row` | number | `3` | Number of event thumbnail columns |

## File Naming Convention

The card expects Reolink FTP push file naming:

- **MP4**: `{Camera name}_00_YYYYMMDDHHMMSS.mp4` — event recording
- **JPG**: `{Camera name}_00_YYYYMMDDHHMMSS.jpg` — thumbnail (~5s after MP4 start)
- **Timelapse**: `timelapse.mp4` at the day level (compiled daily at 01:00)

JPG/MP4 pairing: each thumbnail is matched to the MP4 with the closest earlier timestamp within a 15-second window.

## Development

```bash
npm install
npm run dev          # Vite dev server
npm run build       # Production build
npm test             # Run tests
npm run test:watch   # Watch mode
```

### Deploying to Home Assistant

See `AGENTS.md` and `local_env.md` for deploy configuration. In short:

```bash
npm run build && bash scripts/deploy.sh
```

The deploy script copies the built JS file to your HA instance via SCP and updates the `lovelace_resources` cache-busting tag via WebSocket API.

## Technology

- [Lit 3](https://lit.dev/) + TypeScript
- Vite + Rollup for single-file output
- No external runtime dependencies — runs entirely inside HA's authenticated session
